03 · Conceito

O QUE É UM PROGRAMA?

Instruções simples → tarefas complexas

  O computador

O computador executa instruções simples: somar números, comparar valores, guardar dados na memória. Um programa é uma sequência dessas instruções simples, organizadas para que o computador realize uma tarefa complexa — como rodar um jogo.

  Pense numa receita

Assim como uma receita de bolo é uma lista de passos simples (quebrar ovo, misturar, assar) que juntos produzem algo complexo, um programa é uma lista de instruções simples que juntas produzem um jogo inteiro.

A regra de ouro Você escreve as instruções. O computador obedece — exatamente como está escrito, nem mais, nem menos.
04 · Conceito

A LINGUAGEM DE PROGRAMAÇÃO

Como conversar com o computador

🤖 Computadores são literais

Eles não entendem ambiguidades ou entrelinhas. Se você escrever algo errado, o computador não "adivinha" o que você quis dizer.

🗣️ Linguagem humana é confusa

Tem muitas gírias, duplos sentidos e depende de contexto. Ótima entre pessoas, péssima para dar ordens exatas a uma máquina.

A solução: GDScript Linguagens de programação são conjuntos de comandos claros e exatos. GDScript é a linguagem oficial do Godot, criada exclusivamente para desenvolvimento de jogos.
O que é um script, na prática? É só um arquivo de texto comum, com extensão .gd, onde você escreve essas instruções — nada mágico, é texto puro que o Godot sabe ler.

Pense numa lista de compras com subitens:

Frutas

Ninguém precisa explicar que maçã e banana são frutas — o recuo já diz isso. O GDScript funciona exatamente assim: tudo que está recuado abaixo de uma linha pertence àquela linha.

É a causa nº1 de erro de quem está começando Se o recuo estiver errado, o Godot não entende o código e acusa erro de sintaxe. O QUE É UMA FUNÇÃO

Um bloco de instruções com um nome

Uma função é um pedaço de código que você separa e dá um nome. Só isso. Em vez de deixar cinquenta instruções soltas, você junta as que fazem parte da mesma tarefa e batiza o grupo — igual a "fazer café" numa receita, que por dentro é ferver a água, passar o pó e servir.

funcpalavra-chave: começa uma função
 fazer_cafeo nome que você escolhe
()obrigatórios, mesmo vazios
-> void"não devolve nada"
:abre o bloco indentado
Os dois-pontos e o recuo, de novo Depois do : vem o bloco indentado — a regra do slide anterior. É o recuo que diz onde a função começa e onde ela termina. Não existe nada marcando o fim: a função acaba quando o recuo acaba.
Coffee.gd
●●●
func fazer_cafe() -> void:
    # ferver a água
    # passar o pó
    # servir na xícara
E esse -> void? É a promessa do que a função devolve para quem a usou. void quer dizer "não devolve nada" — ela faz o serviço e pronto. Funções que devolvem alguma coisa existem, e têm um slide só pra elas mais à frente.
Escrever a função não faz nada acontecer Este código sozinho não ferve água nenhuma — ele só ensina ao Godot o que "fazer café" significa. Alguém ainda precisa pedir. E a próxima pergunta é essa: quem pede primeiro?
08 · Fundamentos

POR ONDE O PROGRAMA COMEÇA?

Um script com cinco funções. Qual delas roda primeiro?

Você já sabe que uma função é um bloco de código com um nome. Mas imagine um script com cinco funções, uma embaixo da outra. Quando o jogo começa, por qual bloco o computador começa? Por nenhum — um bloco só roda se alguém pedir. E quem pede primeiro é o próprio Godot: ele procura no seu script uma função chamada _ready e executa ela. É de dentro dela que todo o resto do seu código vai sair.

GameManager.gd
●●●
extends Node

# o Godot executa este bloco sozinho,
# assim que a peça entra no jogo
func _ready() -> void:
    # tudo que tem que acontecer
    # no começo vai aqui dentro
O nome tem que ser exatamente esse O Godot procura por _ready, com o underline na frente. Escreveu ready ou _Ready? A engine não acha, seu bloco nunca roda — e nenhum erro aparece. O jogo só fica parado.
O _ no começo é o aviso Toda função que começa com underline é da engine, não sua: o Godot já sabe o nome dela e a chama na hora certa. Existem várias — _ready é a única que você precisa agora.
Quando exatamente ela roda? Uma única vez, no instante em que a peça "nasce" dentro do jogo — antes de o jogador ver qualquer coisa. Por isso ela é o lugar de preparar as coisas: definir valores iniciais, montar o cenário, começar a música.
E o extends Node na primeira linha? Diz a que tipo de peça este script está preso — aqui, um Node, a peça mais básica do Godot. Não precisa entender a fundo agora; isso é o assunto do próximo módulo. Por ora: Node é uma peça do jogo, e o script é o comportamento que você dá a ela.
09 · Prática

CHAMANDO UMA FUNÇÃO

São duas coisas diferentes: escrever a função e mandar ela rodar

Declarar — ensinar o que a função faz

func fazer_cafe() -> void:

Começa com func e termina com :. Acontece uma vez só no arquivo. Sozinha, não faz nada — é uma receita guardada na gaveta.

Chamar — mandar fazer agora

fazer_cafe()

Sem func, sem : — só o nome e os parênteses. Pode aparecer quantas vezes você quiser. É isto que faz a coisa acontecer.

O _ready é a exceção Ele é a única função do arquivo que você declara e nunca chama — quem chama é a engine, uma vez só. Daí em diante a corrente de chamadas é toda sua.

Aperte Executar e acompanhe a linha acesa. Repare que a execução salta para dentro da função e depois volta exatamente para onde parou:

Coffee.gd
●●●
func _ready() -> void:
    fazer_cafe()   # salta para a linha 5 ↓
    lavar_a_xicara()  # ↑ e volta para cá

func fazer_cafe() -> void:
    ferver_agua()
    colocar_po()
    servir_na_xicara()
Os comentários do slide anterior viraram código "ferver a água" virou ferver_agua(). Cada uma dessas três é outra função, escrita em outro lugar do arquivo — e cada uma pode chamar outras. Um jogo inteiro é isso: funções pequenas chamando funções pequenas.

COMO NOMEAR AS COISAS

Duas regras que valem para todo nome que você escrever no curso

1. O que o Godot não aceita Nome de variável ou função não pode ter espaços, acentos, começar com número, nem ser uma palavra reservada — as que o GDScript já usa, como if, func ou var. Por convenção, escrevemos tudo_minusculo_com_underline.
2. Escreva em português, sem acento Nesta aula os nomes vão em português — o que você está aprendendo já é difícil o bastante sem ter que traduzir cada palavra. Só lembre: fazer_cafe, não fazer_café. O acento fica de fora do nome, mas pode aparecer à vontade nos textos que o jogador lê.
Naming.gd
●●●
# ✅ minúsculo, com underline, sem acento
func fazer_cafe() -> void:

# ❌ o acento quebra
func fazer_café() -> void:

# ❌ espaço não existe em nome
func fazer cafe() -> void:

# ❌ "func" já é do GDScript
func func() -> void:
Mas o Godot fala inglês As palavras da própria linguagem (func, var, if, print) e os nomes de Node (Sprite2D, AnimationPlayer) você não escolhe — vêm assim e assim ficam. O que você batiza é que vai em português. Mais para a frente, quando procurar tutorial na internet, vai ser tudo em inglês: por isso vale ir guardando as palavras que aparecem.

A FUNÇÃO PRINT()

Exibindo mensagens no console

Repare no que está acontecendo aqui: print(...) é uma chamada de função — exatamente o que você acabou de aprender. A diferença é que essa função você não precisou escrever: ela já vem pronta no GDScript. Ela mostra no painel Output o que você colocar entre os parênteses, e é a sua principal ferramenta para descobrir o que o código está fazendo.

Script.gd
●●●
func _ready() -> void:
    print("Olá, Godot!")
    print("Meu primeiro script!")
Output
Onde fica o Output? Dentro do editor do Godot, é o painel na parte de baixo da tela chamado "Output" — ele aparece automaticamente quando você roda o projeto (tecla F5).
Repare nas aspas Texto vai sempre entre aspas — sem elas, o Godot acha que você escreveu o nome de alguma coisa e reclama que não conhece. E dentro das aspas vale tudo: acento, cedilha, ponto de exclamação. A restrição de acento é só para nomes.

Pensem em variáveis como "caixinhas" na memória. A palavra-chave var cria a caixinha; damos um nome e um tipo para guardar um valor específico.

int

Números inteiros (ex: -1, 0, 10).

padrão: 0
float

Números decimais (ex: 2.5, 9.1).

padrão: 0.0

Valores lógicos (true, false).

func _ready() -> void:

O TIPO DECIDE A CONTA

Lá atrás você escolheu um tipo para cada variável. Agora essa escolha cobra o preço.

Com tipo — você decide

var level : int = 3

Você escreve : int e cravou: só cabe número inteiro ali. Se alguém tentar guardar texto, o Godot avisa na hora de escrever — antes de rodar o jogo.

Sem tipo — o Godot adivinha

var level = 3

Sem o : int, o Godot olha o valor, vê um 3 e decide sozinho que é um int. Funciona — mas quem escolheu o tipo foi ele, não você. E é aí que mora a pegadinha ao lado.

Neste curso, escreva sempre o tipo Custa quatro caracteres e transforma erro de execução em erro de digitação — que é infinitamente mais fácil de achar.

Você quer metade de 7. O resultado deveria ser 3.5. Aperte Executar:

Division.gd
●●●
func _ready() -> void:
    var total : int = 7
    print(total / 2)   # cadê o 0.5?

    var exato : float = 7
    print(exato / 2)   # agora sim
Output
Por que o 3 e não o 3.5? Um int é a caixinha de números inteiros: o 0.5 simplesmente não cabe e é jogado fora. Dividir int por int sempre devolve int. Para ter o decimal, um dos dois lados precisa ser float — ou a variável, ou o número (total / 2.0). E nenhum erro aparece: o jogo roda feliz com a conta errada. Guarde este, ele volta.

ARGUMENTOS

Enviando valores para funções

Uma variável criada dentro de uma função só existe ali dentro — isso se chama escopo. Quando outra função precisa daquele valor, ele tem que ser entregue na mão: é para isso que servem os parênteses que até agora estavam vazios.

Arguments.gd
●●●
func _ready() -> void:
    var pontos_do_jogador : int = 4
    mostrar_pontos(pontos_do_jogador)  # entrega o valor ↓

# recebe um int e chama ele de "valor" aqui dentro
func mostrar_pontos(valor : int) -> void:
    print(valor)
Output
Erro clássico de escopo Se você tentar usar pontos_do_jogador lá dentro de mostrar_pontos sem ter passado como argumento, o Godot acusa "Identifier not found" — "não achei ninguém com esse nome". Guarde essa mensagem, ela volta no próximo checkpoint.
Os dois nomes são diferentes de propósito Lá fora é pontos_do_jogador; aqui dentro, valor. O que viaja é o valor (o 4), não o nome — quem recebe escolhe como chamar.

RETORNO DE VALORES

Funções que processam e devolvem um resultado

Agora que sabemos como processar variáveis, podemos criar uma função que processa um valor e retorna um resultado para quem a chamou. Lembra do -> void que vimos lá no início? Significa "não retorna nada". Agora vamos ver o oposto: na declaração, especificamos o tipo do valor retornado usando a seta -> tipo:.

Return.gd
●●●
func _ready() -> void:
    var resultado = somar(8, 7)
    print(resultado) # Saída: 15

# Função que recebe inteiros e retorna um inteiro
func somar(primeiro: int, segundo: int) -> int:
    return primeiro + segundo
Output
Lembrete Quando uma função encontra a palavra return, ela termina seu processo imediatamente — qualquer código escrito depois do return, dentro daquela função, nunca é executado.

ESTRUTURAS CONDICIONAIS

O poder de decisão do seu código (if, else e elif)

Para criar uma estrutura condicional usamos a palavra if (se) seguida de uma condição booleana. O código só entra naquele bloco se a condição for verdadeira.

ifSe a condição for true, executa
elseSenão (se o if falhar), executa
elifSenão se — testa outra condição
● ● ● 
func ver_nota():
    var pontos = 50

    if pontos >= 70:
        print("Aprovado")
    else:
        print("Reprovado")
Output
func ver_nota():
    var pontos = 85

    if pontos >= 90:
        print("Nota A")
    if pontos >= 80:
        print("Nota B")
    if pontos >= 70:
        print("Nota C")
Output
Com vários if soltos, o Godot testa todas as condições — repare que duas linhas são impressas!
func ver_nota():

Com elif, assim que uma condição é verdadeira, o Godot para de testar as outras — só um bloco roda.

REPETIÇÃO: WHILE

O loop condicional (Enquanto...)

Repete um bloco de código enquanto uma condição for verdadeira. Imagine o while como um if que se repete sem parar até a condição falhar!

Cuidado com loops infinitos! A condição dentro do while deve eventualmente se tornar false. Caso contrário, o jogo vai travar para sempre executando aquele bloco.
💖 health: 3
WhileLoop.gd
●●●
func _ready() -> void:
    var vida = 3

    while vida > 0:
        print("Ainda estou vivo!")
        vida -= 1
Output
E o do while? Algumas linguagens têm um terceiro laço, o do while, que executa o bloco uma vez antes de testar a condição. GDScript não tem esse laço. Se você precisar do mesmo efeito, escreva o bloco uma vez e depois o while — mas na prática, quase nunca é necessário.

GUARDANDO VÁRIAS COISAS: ARRAY

Quando uma caixinha não basta

Uma variável guarda um valor. Mas e a mochila do jogador, que pode ter poção, espada e chave ao mesmo tempo? Criar item1, item2, item3 não escala. Para isso existe o Array: uma variável que guarda uma lista de valores em ordem.

A contagem começa no zero O primeiro item é o [0], o segundo é o [1]. É a mesma lógica do range() que acabamos de ver — e é a fonte de erro mais comum com listas.
Array.gd
●●●
func _ready() -> void:
    var mochila = ["poção", "espada"]

    print(mochila[0])      # poção
    print(mochila.size()) # 2 (quantos itens)

    mochila.append("chave") # adiciona no fim
    mochila.erase("espada") # remove pelo valor

    # o for percorre a lista inteira
    for item in mochila:
        print(item)
Repare no for aqui Ele não usa range() — percorre a lista direto, item por item. É a forma mais comum de usar for em jogos, e vai ser exatamente assim que o inventário vai desenhar cada item na tela lá no Módulo 9.

GUARDANDO PARES: DICTIONARY

Quando a posição não importa, mas o nome sim

No Array você busca pela posição (mochila[0]). Mas nem sempre a ordem faz sentido: se você quer saber o dano da espada, não interessa se ela é a primeira ou a terceira da lista.

O Dictionary guarda pares de chave → valor. Você busca pelo nome, não pela posição.

Como escolher entre os dois Precisa de uma coleção em ordem (os itens da mochila)? Array. Precisa descrever uma coisa com vários atributos (nome, dano, preço)? Dictionary. No inventário do seu jogo você vai usar os dois juntos: um Array de Dictionaries.
Dictionary.gd
●●●
func _ready() -> void:
    var espada = {
        "nome": "Espada de Ferro",
        "dano": 12,
        "preco": 150
    }

    print(espada["nome"])   # Espada de Ferro
    espada["dano"] = 15  # muda o valor

    # um Array de Dictionaries = um inventário
    var pocao = {"nome": "Poção", "cura": 20}
    var inventario = [espada, pocao]

DESAFIO!

Juntando todo o conhecimento

👾 Crie uma função batalha()

  • Crie variáveis para a vida do monstro (ex: 30) e seu dano (ex: 10).
  • Use um while que rode enquanto a vida for maior que zero.
  • Dentro do laço, subtraia o dano da vida (use -=).
  • Ainda no laço, um if/else: vida em 0 imprime "Monstro Derrotado"; senão, a vida restante.
Só pra deixar claro Aqui só a vida do monstro cai — é uma simplificação para praticar while + if/else.
Hora de codar! Chame batalha() dentro do _ready() — declarar não basta.
Challenge.gd — esqueleto
●●●
func batalha() -> void:
    var vida_do_monstro : int = 30
    var dano_do_ataque : int = 10
    # seu código aqui...
💡 Dica 1 — por onde começar

Comece pelo while vida_do_monstro > 0: — é a condição que mantém a luta acontecendo.

💡 Dica 2 — dentro do laço

Primeiro subtraia o dano (vida_do_monstro -= dano_do_ataque), depois faça o if/else checando se vida_do_monstro <= 0.

💡 Dica 3 — cuidado com a ordem

Subtraia o dano primeiro, depois cheque a vida. Ao contrário, a mensagem final sai uma repetição atrasada.

O QUE VOCÊ APRENDEU HOJE

Guarde estes seis nomes — eles voltam em todas as aulas daqui pra frente

varGuarda um valor com nome e tipo
funcAgrupa instruções, recebe e devolve valores
ifFaz o código decidir
forRepete um número conhecido de vezes
whileRepete enquanto algo for verdade
[ ] { }Guardam listas e pares chave-valor
As quatro pegadinhas que mais vão te pegar indentação errada; um = onde deveriam ser dois ==; variável criada dentro de uma função que outra não enxerga (escopo); e a divisão de int por int que come o decimal sem dar erro nenhum. Quando algo não funcionar, comece por essas quatro.
