02 · Conceito

O QUE É UM PROGRAMA?

Instruções simples → tarefas complexas

  O computador

O computador executa instruções simples: somar números, comparar valores, guardar dados na memória. Um programa é uma sequência dessas instruções simples, organizadas para que o computador realize uma tarefa complexa — como rodar um jogo.

  Pense numa receita

Assim como uma receita de bolo é uma lista de passos simples (quebrar ovo, misturar, assar) que juntos produzem algo complexo, um programa é uma lista de instruções simples que juntas produzem um jogo inteiro.

A regra de ouro Você escreve as instruções. O computador obedece — exatamente como está escrito, nem mais, nem menos.
03 · Conceito

A LINGUAGEM DE PROGRAMAÇÃO

Como conversar com o computador

🤖 Computadores são literais

Eles não entendem ambiguidades ou entrelinhas. Se você escrever algo errado, o computador não "adivinha" o que você quis dizer.

🗣️ Linguagem humana é confusa

Tem muitas gírias, duplos sentidos e depende de contexto. Ótima entre pessoas, péssima para dar ordens exatas a uma máquina.

A solução: GDScript Linguagens de programação são conjuntos de comandos claros e exatos. GDScript é a linguagem oficial do Godot, criada exclusivamente para desenvolvimento de jogos.
O que é um script, na prática? É só um arquivo de texto comum, com extensão .gd, onde você escreve essas instruções — nada mágico, é texto puro que o Godot sabe ler.

05 · Fundamentos

SINTAXE: INDENTAÇÃO

O recuo não é enfeite — é ele que define o que pertence a quê

Pense numa lista de compras com subitens:

Frutas
    maçã
    banana
Limpeza
    sabão

Ninguém precisa explicar que maçã e banana são frutas — o recuo já diz isso. O GDScript funciona exatamente assim: tudo que está recuado abaixo de uma linha pertence àquela linha.

Indentation.gd
●●●
func check_health() -> void:
    # tudo recuado aqui "pertence" à função
    if health <= 0:
        # e isso "pertence" ao if, dentro da função
        print("Game Over")
É a causa nº1 de erro de quem está começando Se o recuo estiver errado, o Godot não entende o código e acusa erro de sintaxe. Quando der um erro que parece não fazer sentido, confira a indentação primeiro. Use sempre a tecla Tab para recuar — misturar Tab e espaços é o jeito mais fácil de criar um erro invisível.
Se você já viu outra linguagem Muitas usam chaves { } para marcar onde um bloco começa e termina, e aí o recuo é só estética. GDScript não: aqui o recuo é a marcação. É o mesmo comportamento do Python, se você conhece.

ANATOMIA DE UMA FUNÇÃO

Dividindo código em blocos organizados

O computador lê o código linha por linha, dentro de blocos chamados funções. Toda função, sem exceção, segue este formato:

funcpalavra-chave: começa a função
 nomenome que você escolhe
(args)valores que ela recebe
->  tipoo que ela devolve
:início do bloco (indentado)
Repare nos dois-pontos Depois do : vem o bloco indentado — exatamente a regra que acabamos de ver. Tudo que estiver recuado abaixo da linha do func pertence àquela função.
Ainda não entendi "args" e "-> tipo" Tudo bem — cada uma dessas partes tem um slide só pra ela mais à frente. Por enquanto guarde só o formato geral.
07 · Fundamentos

FUNÇÕES NATIVAS DA ENGINE

As funções que o Godot chama sozinho, sem você pedir

Funções nativas (o "_" no início) Sempre que ver uma função começando com _ (ex: _ready ou _process), significa que é uma função nativa da Engine Godot — ela roda automaticamente em momentos específicos do jogo, você não precisa chamá-la.
GameManager.gd
●●●
extends Node

# Roda 1 vez, quando o Node entra na cena
func _ready() -> void:
    setup_level()

# Roda a cada frame, sem parar, enquanto o jogo estiver aberto
func _process(delta) -> void:
    # instruções que se repetem sem parar...
_ready() Roda uma única vez, assim que o Node "nasce" na cena. Ideal para preparar/configurar algo.
_process() Roda a cada frame, continuamente. Ideal para checar coisas o tempo todo, como teclas pressionadas.
E "extends Node"? Significa que este script herda as características básicas de um Node — o tipo de objeto mais fundamental do Godot, e este é o ícone dele no editor. Não se preocupe em entender Node e Scene a fundo agora: vamos explorar isso com calma no próximo módulo. Por enquanto, pense num Node como "uma peça do seu jogo" e um Script como "o comportamento" que você dá a ela.
06 · Prática

CHAMANDO UMA FUNÇÃO

Escrever a função não faz nada. Ela só roda quando alguém a chama.

Escrever boil_water(), com os parênteses no fim, é chamar (ou "invocar") a função: é isso que manda o computador ir até aquele bloco, executar tudo lá dentro, e voltar para continuar de onde parou.

Funções chamam outras funções — e é assim que um programa cresce Repare que make_coffee() não faz nada sozinha: ela só chama outras três. Cada uma dessas, por sua vez, pode chamar outras. Um jogo inteiro é isso — funções pequenas chamando funções pequenas.
Quem chama a primeira? A Engine. Lembra do _ready()? Ele é chamado pelo Godot automaticamente. Daí em diante, a corrente de chamadas é toda sua.
Example.gd
●●●
func _ready() -> void:
    make_coffee()   # chama ↓

func make_coffee() -> void:
    # não sabe fazer nada sozinha —
    # só organiza o passo a passo:
    boil_water()
    add_coffee(2)
    pour_into_filter()

Por que usar funções?

  • Agrupam comandos: juntam instruções simples numa tarefa complexa.
  • Evitam repetição: escreveu uma vez, chama quantas vezes quiser.
  • Organizam: deixam o projeto muito mais fácil de ler.
07 · Boas práticas

COMO NOMEAR AS COISAS

Duas regras que valem para todo nome que você escrever no curso

1. O que o Godot não aceita Nome de variável ou função não pode ter espaços, acentos, começar com número, nem ser uma palavra reservada — as que o GDScript já usa, como if, func ou var. Por convenção, escrevemos tudo_minusculo_com_underline.
2. Nome em inglês, texto em português Neste curso todo nome vai em inglês — variáveis, funções, componentes, arquivos. Já os textos que o jogador lê continuam em português. As duas coisas convivem na mesma linha sem problema nenhum.
Naming.gd
●●●
# ✅ nome em inglês, mensagem em português
var player_health = 10
print("Vida cheia!")

# ❌ acento no nome quebra
var vida_máxima = 10

# ❌ espaço não existe em nome
var player health = 10
Por que inglês, se a aula é em português? Porque é onde o resto do mundo está: a documentação do Godot, os tutoriais que você vai procurar quando travar, e o código de qualquer equipe. Acostumar desde a primeira linha custa nada agora e economiza muito depois.

VARIÁVEIS & TIPOS

Caixinhas para guardar nossos valores

Pensem em variáveis como "caixinhas" na memória. A palavra-chave var cria a caixinha; damos um nome e um tipo para guardar um valor específico.

int

Números inteiros (ex: -1, 0, 10).

padrão: 0
float

Números decimais (ex: 2.5, 9.1).

padrão: 0.0
bool

Valores lógicos (true, false).

padrão: false
String

Textos (ex: "player").

padrão: ""
Variables.gd
●●●
func _ready() -> void:
    # 1. Com tipo e valor (recomendado)
    var level : int = 3

    # 2. Apenas o tipo (valor padrão atribuído)
    var speed : float

    # 3. Inferência (a Engine adivinha o tipo)
    var player_name = "Hero"

    var is_jumping : bool = false
Qual forma usar? Prefira sempre declarar com o tipo (var level : int = 3) — isso ajuda o Godot a avisar sobre erros antes mesmo de rodar o jogo. Repare também que texto sempre precisa de aspas ("Hero"), mas número não. Por convenção, nomes de variáveis também usam tudo_minusculo_com_underline, sem espaços ou acentos.
09 · Fundamentos

ARGUMENTOS

Enviando valores para funções

Quando uma variável é declarada dentro de uma função, ela só existe dentro daquele bloco — isso se chama escopo: o "território" onde uma variável existe. Para que outras funções saibam os valores da variável, precisamos enviar o valor (argumento) da função que chama para a que recebe. A função receptora precisa especificar o nome e o tipo de dado que espera receber, igual a uma variável!

Arguments.gd
●●●
func _ready() -> void:
    var num = 4
    print_number(num) # chamando e enviando

# função que recebe um (num) do tipo inteiro
func print_number(num: int) -> void:
    print(num)
Output
Erro clássico de escopo Se você tentar usar a variável num de dentro de _ready() em outra função sem passá-la como argumento, o Godot vai acusar algo como "Identifier not found". Guarde essa mensagem — você vai encontrá-la de novo!
Argumento ou parâmetro? Os dois nomes aparecem por aí e a diferença é simples: o parâmetro é o nome declarado na função (num: int ali na linha 6); o argumento é o valor que você realmente manda na hora de chamar (o 4). Se alguém usar um pelo outro, ninguém morre — mas agora você sabe.

11 · Fundamentos

OPERAÇÕES LÓGICAS

Perguntas que retornam Verdadeiro (true) ou Falso (false)

A pegadinha nº1 de quem está começando Um único = atribui um valor (idade = 10 → guarda 10 na variável). Dois sinais == comparam se dois valores são iguais e devolvem true/false (idade == 10 → pergunta "idade é igual a 10?"). Se seu código não fizer o esperado, esse é sempre um bom primeiro lugar pra checar.
==Igual a
!=Diferente de
>Maior que
<Menor que
>=Maior ou igual a
<=Menor ou igual a
andVerdadeiro se os dois forem
orVerdadeiro se pelo menos um for
notNegação de um valor (oposto)
Logic.gd
●●●
func _ready() -> void:
    var x = true
    var y = false
    var z = 83

    var a = x and y   # a = false (pois y é false)
    var b = x or y    # b = true (pois x é true)
    var c = not x     # c = false (oposto de true)
    var d = z == 30 + 53  # d = true (83 é igual a 83)
    var e = z > 100    # e = false (83 não é maior que 100)

Repare: toda operação lógica sempre devolve um valor bool — true ou false.

RETORNO DE VALORES

Funções que processam e devolvem um resultado

Agora que sabemos como processar variáveis, podemos criar uma função que processa um valor e retorna um resultado para quem a chamou. Lembra do -> void que vimos lá no início? Significa "não retorna nada". Agora vamos ver o oposto: na declaração, especificamos o tipo do valor retornado usando a seta -> tipo:.

Return.gd
●●●
func _ready() -> void:
    var result = add(8, 7)
    print(result) # Saída: 15

# Função que recebe inteiros e retorna um inteiro
func add(a: int, b: int) -> int:
    return a + b
Output
Lembrete Quando uma função encontra a palavra return, ela termina seu processo imediatamente — qualquer código escrito depois do return, dentro daquela função, nunca é executado.

ESTRUTURAS CONDICIONAIS

O poder de decisão do seu código (if, else e elif)

Para criar uma estrutura condicional usamos a palavra if (se) seguida de uma condição booleana. O código só entra naquele bloco se a condição for verdadeira.

ifSe a condição for true, executa
elseSenão (se o if falhar), executa
elifSenão se — testa outra condição
● ● ● 
func check_score():
    var score = 50

    if score >= 70:
        print("Aprovado")
    else:
        print("Reprovado")
Output
func check_score():
    var score = 85

    if score >= 90:
        print("Nota A")
    if score >= 80:
        print("Nota B")
    if score >= 70:
        print("Nota C")
Output
Com vários if soltos, o Godot testa todas as condições — repare que duas linhas são impressas!
func check_score():
    var score = 85

    if score >= 90:
        print("Nota A")
    elif score >= 80:
        print("Nota B")
    elif score >= 70:
        print("Nota C")
    else:
        print("Reprovado")
Output
Com elif, assim que uma condição é verdadeira, o Godot para de testar as outras — só um bloco roda.

func _process(delta):

REPETIÇÃO: WHILE

O loop condicional (Enquanto...)

Repete um bloco de código enquanto uma condição for verdadeira. Imagine o while como um if que se repete sem parar até a condição falhar!

Cuidado com loops infinitos! A condição dentro do while deve eventualmente se tornar false. Caso contrário, o jogo vai travar para sempre executando aquele bloco.
💖 health: 3
WhileLoop.gd
●●●
func _ready() -> void:
    var health = 3

    while health > 0:
        print("Ainda estou vivo!")
        health -= 1
Output
E o do while? Algumas linguagens têm um terceiro laço, o do while, que executa o bloco uma vez antes de testar a condição. GDScript não tem esse laço. Se você precisar do mesmo efeito, escreva o bloco uma vez e depois o while — mas na prática, quase nunca é necessário.

GUARDANDO VÁRIAS COISAS: ARRAY

Quando uma caixinha não basta

Uma variável guarda um valor. Mas e a mochila do jogador, que pode ter poção, espada e chave ao mesmo tempo? Criar item1, item2, item3 não escala. Para isso existe o Array: uma variável que guarda uma lista de valores em ordem.

A contagem começa no zero O primeiro item é o [0], o segundo é o [1]. É a mesma lógica do range() que acabamos de ver — e é a fonte de erro mais comum com listas.
Array.gd
●●●
func _ready() -> void:
    var backpack = ["poção", "espada"]

    print(backpack[0])      # poção
    print(backpack.size()) # 2 (quantos itens)

    backpack.append("chave") # adiciona no fim
    backpack.erase("espada") # remove pelo valor

    # o for percorre a lista inteira
    for item in backpack:
        print(item)
Repare no for aqui Ele não usa range() — percorre a lista direto, item por item. É a forma mais comum de usar for em jogos, e vai ser exatamente assim que o inventário vai desenhar cada item na tela lá no Módulo 9.

GUARDANDO PARES: DICTIONARY

Quando a posição não importa, mas o nome sim

No Array você busca pela posição (backpack[0]). Mas nem sempre a ordem faz sentido: se você quer saber o dano da espada, não interessa se ela é a primeira ou a terceira da lista.

O Dictionary guarda pares de chave → valor. Você busca pelo nome, não pela posição.

Como escolher entre os dois Precisa de uma coleção em ordem (os itens da mochila)? Array. Precisa descrever uma coisa com vários atributos (nome, dano, preço)? Dictionary. No inventário do seu jogo você vai usar os dois juntos: um Array de Dictionaries.
Dictionary.gd
●●●
func _ready() -> void:
    var sword = {
        "name": "Espada de Ferro",
        "damage": 12,
        "price": 150
    }

    print(sword["name"])   # Espada de Ferro
    sword["damage"] = 15  # muda o valor

    # um Array de Dictionaries = um inventário
    var inventory = [sword, potion]

DESAFIO!

Juntando todo o conhecimento

👾 ⚔️ Crie uma função battle() que simule uma luta!

  • Crie variáveis para a vida do monstro (ex: 30) e seu dano de ataque (ex: 10).
  • Use um while que continue enquanto a vida do monstro for maior que zero.
  • Dentro do laço, subtraia o seu dano da vida do monstro (use -=).
  • Ainda no laço, use um if/else: se a vida chegar a 0, imprima "Monstro Derrotado"; senão, a vida restante.
Só pra deixar claro Aqui só a vida do monstro diminui — o seu personagem não recebe dano. É uma simplificação para praticar while + if/else juntos.
Hora de codar! Abra o Godot e chame battle() dentro do _ready().
Challenge.gd — esqueleto
●●●
func battle() -> void:
    var monster_health : int = 30
    var attack_damage : int = 10

    # seu código aqui...

Travou? Abra uma dica de cada vez.

💡 Dica 1 — por onde começar

Comece pelo while monster_health > 0: — é a condição que mantém a luta acontecendo.

💡 Dica 2 — dentro do laço

Primeiro subtraia o dano (monster_health -= attack_damage), depois faça o if/else checando se monster_health <= 0.

💡 Dica 3 — cuidado com a ordem

Se você checar a vida antes de subtrair o dano, sua mensagem final vai aparecer uma repetição atrasada. Subtraia primeiro, depois cheque.
