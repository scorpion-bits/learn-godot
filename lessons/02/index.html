O AVISO DE FÍSICA

O corpo precisa de um formato!

Ao criar o CharacterBody2D, o Godot exibe um sinal de Warning (Aviso) amarelo na árvore.

Por que o erro aparece?

O CharacterBody entende física, mas ele não tem formato! Ele não sabe se o personagem é grande, pequeno, quadrado ou redondo.

Warning não é Error O triângulo amarelo é só um aviso — o jogo ainda roda! Mas até você resolver, esse Node não vai colidir com nada: o personagem vai atravessar paredes e chão como um fantasma.

AJUSTANDO A COLISÃO

Encaixando o Shape no Sprite

Agora que temos uma imagem como referência visual, voltamos ao nosso CollisionShape2D para darmos o tamanho real do nosso corpo.

No editor do Godot (Viewport 2D), usamos as alças vermelhas para esticar a borda azul e "envelopar" apenas os pés do player, simulando o efeito de profundidade num RPG Top-Down.
Por que só os pés? Se a colisão cobrisse o corpo inteiro, o personagem "esbarraria" em qualquer coisa acima dele visualmente, mesmo objetos que deveriam estar atrás dele na tela. Colidindo só com os pés, ele pode passar visualmente por trás de árvores, paredes baixas etc., e o jogo ainda calcula a física corretamente pelo chão.

ENTENDENDO O VECTOR2

A bússola matemática do Godot

Um tipo novo, além de int/float/bool/String Lá na Aula 1 vimos que var guarda um valor de um tipo (um número, um texto...). Vector2 é só mais um tipo — só que em vez de guardar um número, ele guarda dois números juntos, sempre em par: um x e um y.

Ouviremos nossos botões usando o Vector2, que armazena duas informações de Eixo (X e Y):

X é Horizontal (+ Direita, - Esquerda).
Y é Vertical (+ Baixo, - Cima).
A direção combinada aponta para onde o personagem vai.

CRIANDO O INPUT COMPONENT

Adicionando um Node Básico e seu script

O Node Básico

Usamos este Node (que é invisível e não tem física) apenas para guardar a lógica. Renomeamos para InputComponent e adicionamos um Script. Ele será o ouvido do jogo!

W
A
S
D
InputComponent.gd
●●●
extends Node

func get_direction() -> Vector2:
    var direction = Input.get_vector(
        "ui_left",   # Esquerda (A)
        "ui_right",  # Direita (D)
        "ui_up",     # Cima (W)
        "ui_down"    # Baixo (S)
    )
    return direction
O que get_vector() faz? Ele recebe 4 ações (esquerda, direita, cima, baixo) e devolve um único Vector2 já combinando as duas opostas em cada eixo — se você segurar A e D juntos, por exemplo, o resultado em X é zero, eles se cancelam. É por isso que dá pra andar na diagonal apertando duas teclas.

CRIANDO O MOVEMENT COMPONENT

Adicionando as pernas da nossa arquitetura

Mais um Node Básico

Mesma ideia do InputComponent: um Node invisível e sem física, só que este guarda a lógica de andar. Renomeamos para MovementComponent e adicionamos um Script. A especialidade dele é pegar uma direção vetorial e aplicar a física de movimento.

Usamos @export var body para criarmos uma gaveta no Inspector. Assim, o próprio Player (CharacterBody2D) é arrastado pra lá, e o Node sabe QUEM ele vai empurrar.
Uma variável pode guardar um Node inteiro Repare que o tipo depois dos dois-pontos não é int nem String como na Aula 1 — é CharacterBody2D. Uma variável pode guardar qualquer tipo de coisa, até a referência a um Node inteiro da sua Scene, não só números e textos.
MovementComponent.gd
●●●
extends Node

@export var body: CharacterBody2D
@export var speed: int = 200

func move(direction: Vector2):
    if body:
        # Direção * Velocidade
        body.velocity = direction * speed
        body.move_and_slide()

FUNÇÕES NATIVAS & DELTA

O coração pulsante da Engine Godot

Na engine, toda função que começa com um underline _ é uma Função Nativa (Callback). Elas são chamadas automaticamente pelo motor do jogo.

_process()

Roda o mais rápido que seu PC aguentar. Usado para gráficos e lógica visual (ex: UI, Temporizadores, Interações Simples).

_physics_process()

Roda cravado a 60 vezes por segundo em qualquer PC. Usado sempre que formos lidar com Física (Movimentação e Colisões).

Nativas.gd
●●●
extends Node

func _process(delta: float):
    # FPS Variável - Pode rodar a 300fps num PC Gamer
    print("Renderizando Gráficos!")

func _physics_process(delta: float):
    # Exatos 60 FPS Fixos - A física nunca quebra
    print("Calculando a Física!")
E o tal do delta? É o tempo que passou desde o último frame (ex: 0.016s). Se multiplicarmos nossa velocidade pelo delta, garantimos que o boneco ande a mesma distância num PC ultra-rápido e num notebook antigo, mantendo o jogo justo!
18 · Fundamentos

A FÍSICA NO CÓDIGO

Dissecando o Movement Component

Acabamos de usar dois conceitos absurdamente mágicos do CharacterBody2D que precisamos entender a fundo:

body.velocity

Nós não precisamos declarar essa variável! A velocity já existe em todo CharacterBody. Ela guarda a inércia, informando matematicamente ao motor do jogo a direção e a força que o boneco está indo.

body.move_and_slide()

Sem essa linha, o boneco não anda! É o "Execute" da física. Ela pega a velocity e empurra o corpo. Se o corpo bater na quina de uma parede, essa função desliza ele lindamente, evitando que o player "trave" nas quinas!

JUNTANDO TUDO NO PAI (PLAYER)

Testando o movimento antes da arte

A Orquestração

Já temos Input e Movement. O Pai (Player.gd) agora atua como um maestro para ligar os ouvidos nas pernas, e garantir que a física funcione pura e perfeitamente!

O que é esse "$"? $NomeDoNode é um atalho do Godot para "pegar a referência de um Node filho pelo nome" — $InputComponent significa "me dê o Node chamado InputComponent que está dentro desta Scene".
Por que @onready? Quando o script começa a rodar, a Scene ainda não terminou de montar seus Nodes filhos — então $InputComponent ainda não existiria se rodasse na hora. @onready diz ao Godot "espere a cena terminar de carregar antes de buscar esse valor". Sem ele, o jogo travaria com um erro logo no início.
Player.gd
●●●
extends CharacterBody2D

@onready var input_comp = $InputComponent
@onready var movement_comp = $MovementComponent

func _physics_process(delta: float) -> void:

    # 1. Pega direção das teclas com os Ouvidos
    var direction = input_comp.get_direction()

    # 2. As Pernas lidam com a física
    movement_comp.move(direction)

CRIANDO O VISUAL COMPONENT

Adicionando vida ao personagem que já se move!

O terceiro Node Básico

Nosso bloco já se move perfeitamente. Agora criamos mais um Node invisível, o VisualComponent, para tocar as animações certas por cima dessa movimentação física.

A primeira linha nova: class_name VisualComponent Isso registra este script como um tipo novo em todo o projeto — é por causa dessa linha que outros scripts conseguem escrever @export var input_component : InputComponent (como abaixo) usando o nome da classe, em vez de só "Node" genérico.
VisualComponent.gd
●●●
extends Node

class_name VisualComponent

@export var animation : AnimationPlayer
@export var body : CharacterBody2D
@export var input_component : InputComponent

var last_direction : Vector2 = Vector2.DOWN

func _process(delta: float):
    if(body and animation and input_component.direction != Vector2.ZERO):
        last_direction = body.velocity
        play("running")
    else:
        play("idle")

func play(type : String):
    var anim = type + "_"
    if(abs(last_direction.x) >= abs(last_direction.y)):
        if(last_direction.x > 0):
            anim += "right"
        else:
            anim += "left"
    else:
        if(last_direction.y > 0):
            anim += "down"
        else:
            anim += "up"

    animation.play(anim)

Como o play() escolhe a direção? last_direction guarda o último Vector2 de movimento. Comparando abs(x) com abs(y) (o valor absoluto, ignorando o sinal), descobrimos qual eixo é mais forte: se X venceu, o personagem está indo mais pra esquerda/direita do que pra cima/baixo, então tocamos a animação daquele eixo — e o sinal (positivo ou negativo) decide qual das duas pontas.
