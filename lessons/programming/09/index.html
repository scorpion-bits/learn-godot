03 · Conceito

ONDE MORA O TEXTO DE UM NPC?

A primeira ideia funciona — e para de funcionar no terceiro personagem

❌ O texto dentro do script

Cada NPC ganha um script com as falas escritas no meio do código. Funciona para um. No terceiro, você tem três scripts quase iguais.

E quando o roteirista quiser trocar uma vírgula, ele precisa abrir código — e pode quebrar o jogo sem querer.

✅ O texto como arquivo

A fala vira um arquivo de dados, editado por formulário. O código é escrito uma vez e não sabe o que os personagens dizem.

É a mesma ideia dos componentes: separar o que o jogo faz de o que o jogo contém.

Pensa no cardápio Ninguém reescreve o restaurante para acrescentar um prato — reescreve o cardápio. Falta descobrir que peça do Godot é o cardápio.
04 · Conceito

NODE GUARDA COMPORTAMENTO. RESOURCE GUARDA DADO.

A segunda família de peças do Godot

Node

Existe dentro da cena. Ocupa lugar na árvore, roda _process, aparece na tela. É um ator do jogo.

Resource

Existe como arquivo. Não tem posição, não roda a cada quadro, não aparece sozinho. É uma ficha de dados que qualquer Node pode carregar.

Você já usou Resources sem perceber A Texture2D que você arrastou para o Sprite2D é um Resource. O RectangleShape2D do CollisionShape2D também. A animação que você gravou no AnimationPlayer também.
Por que isso importa hoje Uma fala é dado puro: um texto, uma imagem, um tempo. Nada nela precisa rodar. É exatamente a descrição de um Resource.

Cinco linhas que definem o que é uma fala no seu jogo

DialogueData.gd
●●●
extends Resource
class_name DialogueData

@export var text : String
@export var duration : float
@export var portrait : Texture2D
extends Resource, não Node É essa linha que faz a diferença. Sem ela você teria mais um Node, preso a uma cena. Com ela, você ganha algo que vira arquivo.
O class_name de novo Mesma função dos componentes: registra DialogueData como um tipo do projeto. É por causa dele que o Godot vai oferecer esse tipo na hora de criar o arquivo.
Três campos, três perguntas O que o personagem diz, em quanto tempo a frase aparece na tela, e qual rosto aparece ao lado. O retrato pode ficar vazio — nem toda fala tem dono à vista.
06 · Prática

CADA FALA VIRA UM ARQUIVO

A partir daqui, escrever diálogo é preencher formulário

  1. No painel FileSystem, botão direito numa pasta → New Resource…
  2. Na busca, digite DialogueData — ele aparece porque demos um class_name.
  3. Salve como ferreiro_01.tres, numa pasta dialogues/.
  4. Clique no arquivo: o Inspector mostra os três campos. Preencha.
  5. Repita para cada fala. Uma fala, um arquivo.
O que é um .tres? É o arquivo de Resource do Godot em formato de texto. Dá para abrir num editor de texto e ler — e, porque é texto, funciona bem quando várias pessoas mexem no mesmo projeto.
DialogueData não aparece em New Resource? O class_name só é registrado depois que o script é salvo. Salve o arquivo e tente de novo.

07 · Conceito

UM NODE QUE SEMPRE EXISTE

O diálogo não pertence a nenhuma cena — então ele precisa morar fora de todas

A caixa de diálogo aparece na floresta, na vila e na caverna. Se ela fosse filha de uma dessas cenas, sumiria ao trocar de mapa. O Godot resolve isso com o Autoload: um Node criado no início do jogo, que nunca é destruído e pode ser chamado pelo nome de qualquer script.

Como criar Project ▸ Project Settings ▸ Globals ▸ Autoload. Escolha o script, dê o nome DialogueSystem e clique em Add. Esse nome vira uma palavra que existe no projeto inteiro.
Use com parcimônia Tudo que é global é fácil de chamar e difícil de rastrear. Autoload combina com o que é único no jogo inteiro — o diálogo é; um inimigo não é.
Project Settings — Autoload
Globals
EventSystem event_system.gd
DialogueSystem dialogue_system.gd
Sem class_name, sem $, sem arrastar Depois de registrado, DialogueSystem.start_dialogue(...) funciona em qualquer script do projeto. O nome do Autoload é a referência.
08 · Conceito

UM AVISO QUE O JOGO INTEIRO PODE OUVIR

O EventSystem: o mesmo signal dos Módulos 5 e 6, só que num lugar público

event_system.gd
●●●
extends Node

# Avisos que qualquer parte do jogo pode
# disparar — e qualquer outra pode escutar.
signal dialogue_started
signal dialogue_finished
Por que não avisar direto? Quando o diálogo começa, várias coisas podem querer reagir: o jogador para de andar, o inimigo espera, a música abaixa. O DialogueSystem não precisa conhecer nenhuma delas — ele grita no meio da praça, e quem tiver interesse escuta.
É o padrão do Módulo 6, ampliado Lá a Hitbox avisava e a Hurtbox escutava — um para um, dentro da cena. Aqui o aviso é público: EventSystem.dialogue_started.emit() de um lado, EventSystem.dialogue_started.connect(...) do outro, sem os dois se conhecerem.

10 · Fundamentos

O TEXTO QUE APARECE LETRA POR LETRA

Duas peças novas: visible_ratio e o Tween

visible_ratio

Uma propriedade do RichTextLabel que vai de 0.0 a 1.0 e diz que fração do texto está visível. Em 0.5, metade da frase aparece.

Tween

Um ajudante que muda um número aos poucos, sozinho, ao longo do tempo. Você diz o alvo e a duração; ele cuida de cada quadro.

a ideia
●●●
txt.visible_ratio = 0.0
tween = create_tween()
tween.tween_property(txt,
    "visible_ratio", 1.0, 1.5)
Leia como uma frase "Leve a propriedade visible_ratio daquele Node até 1.0, em 1.5 segundos." O efeito de máquina de escrever é isso — não é um for com espera no meio.
11 · Fundamentos

DURATION NÃO É TEMPO POR LETRA

A pegadinha que faz frase curta parecer lenta e frase longa parecer apressada

tween_property recebe o tempo total da animação. Com duration = 1.5, qualquer frase leva um segundo e meio para aparecer inteira — não importa se tem cinco palavras ou cinquenta.

"Oi." 1,5 s para três letras — arrastado.
"Faz muitos anos que ninguém passa por aqui, viajante…" 1,5 s para a frase toda — voa.
É por isso que duration é um campo do arquivo Cada fala ganha o próprio ritmo, ajustado no Inspector até soar bem. Uma frase de suspense pode querer 3 segundos; um "Ei!" quer 0,3.
Terminou antes? Dá para calcular a duração a partir do tamanho do texto — text.length() * 0.03, por exemplo — e ter o mesmo ritmo em toda fala automaticamente.

O DIALOGUEUI COMPLETO

A caixa só sabe mostrar uma fala. Quem escolhe qual é problema de outro.

DialogueUI.gd
●●●
extends Control
class_name DialogueUI

@onready var portrait : TextureRect = $Portrait
@onready var txt : RichTextLabel = $ColorRect/RichTextLabel
var tween : Tween

func _ready():
    DialogueSystem.register_ui(self)
    hide()

func play_dialogue(dialogue : DialogueData):
    txt.visible_ratio = 0.0
    txt.text = dialogue.text
    if dialogue.portrait:
        portrait.texture = dialogue.portrait
        portrait.visible = true
    else:
        portrait.visible = false
    reset_tween()
    tween = create_tween()
    tween.tween_property(txt, "visible_ratio",
        1.0, dialogue.duration)

func skip_dialogue_animation():
    reset_tween()
    txt.visible_ratio = 1.0

func is_dialogue_playing() -> bool:
    if tween and tween.is_running():
        return true
    return false

func reset_tween() -> void:
    if tween:
        tween.kill()
A UI se apresenta sozinha register_ui(self) no _ready: em vez de o sistema sair procurando a caixa pela árvore, a caixa avisa que chegou. self significa "este Node aqui".
Por que matar o Tween antes de criar outro Se o jogador avança rápido, dois Tweens ficariam mexendo no mesmo visible_ratio ao mesmo tempo, e o texto pisca. kill() desliga o antigo — é o mesmo problema de dois donos da mesma variável que você viu no knockback.
if tween sozinho, sem comparação Uma variável que ainda não recebeu Node nenhum vale null, e null conta como falso. É o mesmo if(!body) do Módulo 3-4, do lado contrário.
13 · Prática

O DIALOGUESYSTEM GUARDA A VEZ

Uma lista de falas e um número: de quem é a vez de falar

dialogue_system.gd
●●●
extends Node

var ui : DialogueUI
var current_dialogues : Array[DialogueData]
var dialogue_count : int

func register_ui(dialogue_ui : DialogueUI):
    ui = dialogue_ui

func start_dialogue(dialogues : Array[DialogueData]):
    dialogue_count = -1
    current_dialogues = dialogues
    EventSystem.dialogue_started.emit()
    _next_dialogue()
    ui.show()
Array[DialogueData] É o Array do Módulo 2 com sobrenome: só aceita DialogueData dentro. Se você tentar guardar outra coisa, o Godot avisa antes de rodar.
Por que começar em -1? Porque a primeira coisa que start_dialogue faz é chamar _next_dialogue(), que soma um antes de falar. Começando em −1, a primeira fala mostrada é a de índice 0.
Repare no ui.show() repetido Ele aparece aqui e também no _on_dialogue_started. Não é engano de digitação: emit() chama quem escuta na hora, antes da linha seguinte rodar. Uma das duas chamadas basta — sobrou uma.
14 · Fundamentos

AVANÇAR OU PULAR?

O mesmo botão faz três coisas diferentes — depende do momento

dialogue_system.gd
●●●
func _next_dialogue():
    if current_dialogues:
        if ui.is_dialogue_playing():
            ui.skip_dialogue_animation()
        elif dialogue_count + 1 < current_dialogues.size():
            dialogue_count += 1
            ui.play_dialogue(
                current_dialogues[dialogue_count])
        else:
            EventSystem.dialogue_finished.emit()
1 Texto ainda aparecendo? Mostra tudo de uma vez. É o "pular a animação" de todo RPG.
2 Texto pronto e ainda tem fala? Passa para a próxima.
3 Acabou a lista? Avisa o jogo inteiro que a conversa terminou.
Por que dialogue_count + 1 < size() Uma lista de 3 falas tem índices 0, 1 e 2. Estando no 2, 2 + 1 < 3 é falso — não há próxima, e o diálogo acaba. É a mesma conta que evita estourar o fim de um Array.
15 · Fundamentos

A TECLA QUE O DIÁLOGO ENGOLE

Ligar e desligar a escuta — e impedir que o mundo reaja junto

dialogue_system.gd
●●●
func _ready() -> void:
    EventSystem.dialogue_started.connect(_on_dialogue_started)
    EventSystem.dialogue_finished.connect(_on_dialogue_finished)
    set_process_unhandled_input(false)

func _unhandled_input(event : InputEvent) -> void:
    if event.is_action_pressed("advance_dialogue"):
        _next_dialogue()
        get_viewport().set_input_as_handled()

func _on_dialogue_started():
    set_process_unhandled_input(true)
    ui.show()

func _on_dialogue_finished():
    set_process_unhandled_input(false)
    ui.hide()
_unhandled_input é o último da fila O Godot oferece a tecla primeiro à interface, depois ao resto. Chega aqui só o que ninguém quis — perfeito para uma ação de mundo.
Escuta desligada por padrão set_process_unhandled_input(false) no _ready: fora do diálogo, esta função nem é chamada. Ela liga quando a conversa começa e desliga quando acaba.
set_input_as_handled() — a parte que salva Sem ela, a mesma tecla que avança a fala também acionaria a interação do NPC de novo, reiniciando a conversa. Isso diz ao Godot: "esta tecla já foi usada, esqueça dela".
16 · Prática

O DIALOGUECOMPONENT

Cinco linhas — e é a única peça que você vai encostar de novo

DialogueComponent.gd
●●●
extends Node
class_name DialogueComponent

@export var dialogues : Array[DialogueData]

func start():
    DialogueSystem.start_dialogue(dialogues)
A regra do Módulo 3-4, de novo Um Node invisível, uma responsabilidade só: guardar quais falas este personagem tem e pedir para começar. Ele não sabe desenhar, não sabe contar, não sabe ler teclado.
O @export com uma lista No Inspector, Dialogues vira um array onde você define o tamanho e arrasta um .tres para cada posição. A ordem ali é a ordem da conversa.
Onde está o resto? Não está. O componente chama um Autoload, e Autoload não precisa ser arrastado nem procurado. É a vantagem que pagamos com a globalidade lá atrás.

O QUE VOCÊ CONSTRUIU HOJE

Saiu de um mundo mudo e chegou num sistema que serve para todo personagem do jogo

Resource guarda dadoNode vive na cena; Resource vira arquivo. Conteúdo virou formulário, não código.
Autoload é o que existe sempreUm Node fora de todas as cenas, chamado pelo nome de qualquer script.
Tween anima um númeroCom visible_ratio, isso vira texto surgindo letra por letra.
Input pode ser consumidoset_input_as_handled() impede que a mesma tecla dispare duas reações.
O padrão de sempreComponente isolado + signal + quem escuta reage. Quarta vez que ele aparece.
Array com tipoArray[DialogueData] só aceita falas — o erro aparece antes de rodar.
Guarde este sistema Tudo que precisar parar o jogo e falar com o jogador — placa, tutorial, aviso de missão — reusa o que você montou hoje. É só criar arquivos novos.
