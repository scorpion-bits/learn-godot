INVENTÁRIO

Um mesmo dado servindo o jogo inteiro

Antes de começar Você já sabe criar Nodes, componentes e ler o teclado. Hoje entra a outra metade do Godot, que quase ninguém apresenta direito no começo: os Resources — as peças que guardam dados em vez de comportamento.

03 · Conceito

COMO O JOGO SABE O QUE É UMA POÇÃO?

A pergunta parece boba. A resposta define a arquitetura do seu jogo.

❌ O caminho que parece mais fácil

Escrever o item direto no código de quem precisa dele. Funciona no primeiro item. No décimo, o nome da poção está escrito em quatro arquivos diferentes, e mudar o ícone significa caçar todos.

DontDoThis.gd
●●●
if item_id == "potion":
    item_name = "Poção de Vida"
    icon = load("res://art/potion.png")
elif item_id == "key":
    item_name = "Chave Enferrujada"
    icon = load("res://art/key.png")
# ...e mais 30 elif conforme o jogo cresce

✅ O que vamos fazer

Tratar "item" como um tipo de dado que existe por conta própria — um arquivo, com campos que você preenche no editor. Quem precisa do item recebe o dado inteiro e pergunta a ele.

E tem um ganho que não é técnico Com os itens virando arquivos, quem cria conteúdo não precisa saber programar. Numa equipe como a de vocês, isso significa que a pessoa de arte ou de game design consegue inventar um item novo sem abrir um script.
04 · Conceito

NODE GUARDA COMPORTAMENTO. RESOURCE GUARDA DADO.

A segunda família de peças do Godot

Node

Existe dentro da cena. Ocupa lugar na árvore, roda _process, aparece na tela. É um ator do jogo.

Resource

Existe como arquivo. Não tem posição, não roda a cada frame, não aparece sozinho. É uma ficha de dados que qualquer Node pode carregar.

Você já usou Resources sem perceber A Texture2D que você arrastou para o Sprite2D é um Resource. O RectangleShape2D do CollisionShape2D também. A animação que você gravou no AnimationPlayer também. Todo esse tempo você estava preenchendo fichas de dados.
Uma analogia O Node é o garçom: anda pelo salão, faz coisas. O Resource é o cardápio: não faz nada sozinho, mas todo mundo consulta, e existe um só para o restaurante inteiro.
O detalhe que pega Um Resource é compartilhado. Se dez poções no mapa apontam para o mesmo arquivo e você mudar um campo dele em tempo de execução, as dez mudam juntas. Hoje isso é o que queremos; guarde a informação para quando não for.
05 · Prática

CRIANDO O ITEMDATA

Sete linhas que definem o que é um item no seu jogo

ItemData.gd
●●●
extends Resource
class_name ItemData

@export var name : String = "Item"
@export var icon : Texture2D
@export_multiline var description : String = ""
extends Resource, não Node É essa linha que faz a diferença. Sem ela você teria mais um Node, que só existe dentro de uma cena. Com ela, você ganha algo que vira arquivo.
O class_name de novo Mesma função dos componentes: registra ItemData como um tipo do projeto. É por causa dele que daqui a pouco vamos poder escrever @export var data : ItemData e o Godot já saber o que esperar.
@export_multiline É o @export de sempre, só que o Inspector mostra uma caixa de texto de várias linhas em vez de uma linha só. Detalhe pequeno que faz diferença para quem vai escrever a descrição.
06 · Prática

CADA ITEM VIRA UM ARQUIVO

A partir daqui, criar item é preencher formulário — não é programar

  1. No painel FileSystem, clique com o botão direito numa pasta → New Resource…
  2. Na busca, digite ItemData — ele aparece na lista porque demos um class_name.
  3. Salve como potion.tres, dentro de uma pasta items/.
  4. Clique no arquivo criado: o Inspector mostra os três campos. Preencha.
O que é um .tres? É o arquivo de Resource do Godot em formato de texto. Pode abrir num editor de texto e ler — e, porque é texto, funciona bem com controle de versão quando várias pessoas mexem no mesmo projeto.

O ITEM LARGADO NO MUNDO

Uma cena só, que se transforma em qualquer item

Repare no que não vamos fazer: uma cena para a poção, outra para a chave, outra para a espada. É uma cena só. O que muda é o ItemData que ela recebe na gaveta do Inspector.

Scene
WorldItem
Sprite2D
CollisionShape2D
Inspector
WorldItem.gd

WorldItem.gd
●●●
extends Area2D
class_name WorldItem

@export var data : ItemData

@onready var sprite : Sprite2D = $Sprite2D

func _ready() -> void:
    if(!data):
        push_error("WorldItem: data wasn't set.")
        return

    # a aparência vem do dado, não do editor
    sprite.texture = data.icon
A linha que faz a mágica é a última Você não escolhe o sprite no editor: o item lê o próprio ícone do dado que recebeu. Arraste key.tres na gaveta e a mesma cena vira uma chave.
09 · Prática

COLETANDO AO ENCOSTAR

O Signal que você viu em Colisores, agora com um propósito

O Area2D dispara o signal body_entered quando um corpo entra nele. Conectamos esse signal a uma função nossa e, dentro dela, entregamos o dado ao inventário de quem encostou.

Repare em quem conhece quem O item não guarda uma referência ao player. Ele reage a quem entrou nele, seja o player, seja outra coisa. Isso é o que mantém as peças soltas umas das outras.
Por que get_node_or_null e não get_node? Porque quem encostou pode não ter inventário nenhum — um inimigo, uma caixa. O get_node derruba o jogo com erro nesse caso; o _or_null devolve null e a gente decide o que fazer.
WorldItem.gd — continuação
●●●
# conectado ao signal body_entered do Area2D
func _on_body_entered(body : Node2D) -> void:
    var inventory = body.get_node_or_null("InventoryComponent")

    if(!inventory):
        return   # quem encostou não coleta itens

    if(inventory.add_item(data)):
        queue_free()   # só some se coube
O item só desaparece se realmente foi guardado Por isso o add_item devolve true ou false. Se a mochila estiver cheia, o item continua no chão em vez de sumir no nada — que é o tipo de bug que o jogador percebe e odeia.
10 · Prática

O INVENTORY COMPONENT

Mais um Node vazio com um script — e por dentro, um Array

InventoryComponent.gd
●●●
extends Node
class_name InventoryComponent

# avisa quem estiver interessado que a lista mudou
signal changed

@export var max_slots : int = 12

var items : Array[ItemData] = []

func add_item(item : ItemData) -> bool:
    if(items.size() >= max_slots):
        return false

    items.append(item)
    changed.emit()
    return true

func remove_item(item : ItemData) -> void:
    items.erase(item)
    changed.emit()
Array[ItemData] — um Array com tipo É o mesmo Array do Módulo 2, só que dizendo o que pode entrar. Se alguém tentar guardar um número aqui, o Godot avisa na hora em vez de deixar o erro aparecer só na hora de desenhar a interface.
Criando o seu próprio Signal Até agora você só usou signals que o Godot oferecia. signal changed cria um novo, e changed.emit() dispara. O inventário não sabe que existe uma interface — ele só grita "mudei!" e quem quiser que escute.
Por que add_item devolve bool? Para quem chamou saber se deu certo. É o mesmo raciocínio do push_error nos outros componentes: falhar em silêncio é o pior comportamento possível.

O nome do Node importa aqui O WorldItem procura por get_node_or_null("InventoryComponent"). Se você renomear o Node na árvore, precisa mudar a string também — senão a coleta para de funcionar e nenhum erro aparece.
E o inimigo? Se um dia quiser que um inimigo carregue itens e os derrube ao morrer, é só arrastar o mesmo InventoryComponent para dentro dele. A peça não sabe nem se importa com quem a carrega.

13 · Prática

MOSTRANDO NA TELA

Uma grade que se redesenha sozinha quando a lista muda

InventoryUI.gd
●●●
extends GridContainer
@export var inventory : InventoryComponent

func _ready() -> void:
    if(!inventory):
        push_error("InventoryUI: inventory wasn't set.")
        return

    # toda vez que a lista mudar, redesenha
    inventory.changed.connect(redraw)
    redraw()

func redraw() -> void:
    for child in get_children():
        remove_child(child)
        child.queue_free()

    for item in inventory.items:
        var slot = TextureRect.new()
        slot.texture = item.icon
        slot.tooltip_text = item.name
        slot.custom_minimum_size = Vector2(48, 48)
        add_child(slot)
inventory.changed.connect(redraw) Aqui está o pagamento do signal que criamos. A interface se inscreve uma vez, no início, e nunca mais precisa perguntar nada. Coletou item? A lista grita, a grade redesenha.
Por que remove_child e queue_free? O queue_free marca o Node para ser apagado no fim do frame — ele ainda está lá quando as linhas seguintes rodam. O remove_child tira da árvore na hora, evitando que os slots velhos apareçam junto com os novos por um instante.
Onde a grade mora Dentro de um CanvasLayer, como você viu na aula de Interface. Assim o inventário fica fixo na tela e não anda junto com a câmera.
14 · Conceito

UM DADO, TRÊS LUGARES

Repare no que foi construído: o ItemData nunca foi copiado

  No chão

O WorldItem lê data.icon para saber como se desenhar.

  Na mochila

O InventoryComponent guarda o próprio ItemData na lista — não um código, não um nome.

  Na tela

A InventoryUI lê item.icon e item.name do mesmo objeto.

Faça o teste mental Você decidiu que a poção agora chama "Elixir" e tem outro ícone. Quantos arquivos você abre? Um — o potion.tres. O chão, a mochila e a interface mudam juntos, porque os três estavam olhando para o mesmo lugar.
E é por isso que ficou fácil crescer Quer que o item cure? Acrescente @export var heal : int ao ItemData. Todos os itens ganham o campo, e quem for usar pergunta ao dado. Nenhum if novo, nenhuma cena nova.
15 · Desafio

DESAFIO — USANDO O ITEM

Coletar é metade. Falta gastar.

🧪 Faça a poção ser consumida

  • Acrescente @export var consumable : bool = false ao ItemData e marque como verdadeiro só na poção.
  • No InventoryComponent, crie use_item(item : ItemData).
  • A função deve verificar se o item é consumível; se for, removê-lo da lista.
  • Chame-a ao apertar uma tecla — crie a ação use_item no Input Map.
  • Confira: o item some da grade da interface sozinho.
Challenge.gd — esqueleto
●●●
func use_item(item : ItemData) -> void:
    # seu código aqui...
💡 Dica 1 — por onde começar

Comece checando if(!item.consumable): return. Sair cedo quando não dá para continuar deixa o resto da função mais limpo.

💡 Dica 2 — reaproveite

Você já tem remove_item(), e ele já dispara o changed. Não escreva de novo o que já existe: chame.

💡 Dica 3 — qual item usar?

Para simplificar, use o primeiro da lista: items[0]. Mas cheque antes se a lista não está vazia, senão o jogo quebra.

No próximo módulo: Status e Perigos Seu personagem coleta coisas, mas nada no mundo consegue machucá-lo. Vamos criar o LifeComponent e um sistema de dano — e você vai ver que ele nasce exatamente do mesmo molde do inventário: um componente, um signal, quem quiser que escute.
